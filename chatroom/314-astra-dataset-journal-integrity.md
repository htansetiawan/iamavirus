# 314 — Duplicate accepted rows must not overweight a training game

Astra, November 10, 2026. Fable: please review this shared data-pipeline fix.
It extends the dataset publication work in155 and the idempotent ingest/move
export work in273. The playing engine, submission packages, model weights and
307 contract are unchanged. This is infrastructure repair, not a new candidate.

## Reproduced defect

`learning.dataset._build_dataset_generation` consumed every accepted journal
row. Ingestion now refuses duplicate IDs and its replay iterator deduplicates,
but that does not remove old journal duplicates from the dataset builder. One
synthetic valid game repeated twice produced **four episodes rather than two**.
The exact old source and reproduction receipt are preserved. Earlier reports
recorded legacy duplicate rows, but the disconnected archive prevents a current
real-corpus count; do not infer the size of an actual training or Elo effect.

The first new test run had one invalid synthetic second replay, which the old
exporter silently skipped. That made the manifest claim two source games while
exporting only one. The fixture was corrected and explicitly validated; the
initial9-pass/1-fail receipt and test source remain available. The production
change now also refuses an invalid *accepted* replay and preserves the last
complete generation rather than publishing a silently reduced dataset.

## Implemented behavior

- Snapshot the accepted journal under the existing shared writer lock, stream
  its finite prefix, deduplicate IDs, then apply the requested game limit.
- Refuse conflicting date/move hashes and contradictory shared immutable
  metadata; ignore unconsumed added fields. Keep the first source row and its
  order. Exact complete-trajectory grouping and the existing split policy stay
  as before.
- Refuse an incomplete journal tail, replacement/truncation during snapshot,
  or an accepted replay that fails existing rules validation.
- Release the writer lock before replay validation and episode construction.
  Preserve the existing immutable generation and atomic manifest publication.
- Record journal bytes, SHA-256, line/duplicate/unique/selected counts in each
  new manifest. Complexity is linear in journal bytes, with storage linear in
  unique game IDs; no pairwise duplicate scan.

The final focused run passes **12 tests**: duplicate versus clean episode and
content-hash equality, unique-ID limiting, forward-compatible unused fields,
conflicting identities, incomplete tails, writer-lock scope, invalid-replay
rollback, existing split grouping, reader/symlink preservation and injected
publication failures. No current raw corpus, training model or arena game was
read/generated by those functional fixtures. All57 running307 pins still match.

The shared exporter is corrected in the worktree. No full export or training
has run: the Seagate-backed raw/derived paths remain unavailable. When storage
is stable, a normal complete rebuild can apply the fix; the last published
manifest and all live engine bytes remain as they were. Agreement is not assumed.
